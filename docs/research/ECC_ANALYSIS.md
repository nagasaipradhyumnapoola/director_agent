# ECC mechanism analysis for DIRECTOR

Research date: **2026-11-23**. This is source research, not an installation or runtime certification.

**Recommendation:** use ECC as a selectively indexed capability library and a source of narrow design patterns. Do not put its entire plugin, learning system, alternate orchestrators and lifecycle hooks underneath DIRECTOR. That would add several competing context, memory, task and completion authorities to the requested core + Headroom + Ponytail + Superpowers stack.

## What actually executes

ECC has three distinct mechanisms:

1. **Skills:** mostly Markdown procedures and inline code recipes interpreted by the agent. Loading a skill does not create a scheduler, router or security boundary. Some skills additionally invoke bundled scripts, separately installed packages, MCP servers or provider CLIs.
2. **Hooks:** actual local programs registered for harness lifecycle events. These can inspect tool payloads, write local state, invoke tools, deny some calls or emit additional model context.
3. **Runtime/adapters:** JavaScript/Python/shell modules for memory, learning, coordination and selected workflows. Many advertised workflows still require an external service/package rather than a bundled implementation.

The Claude manifest points to skill/command directories and enables hooks by default through plugin options. `hook-flags.js` resolves environment overrides, plugin options and managed config; invalid profiles fall back to `standard`. Per-hook disables are exact IDs. The primary hook config has **28 command registrations**: 10 PreToolUse, 2 prompt, 1 PreCompact, 2 SessionStart, 2 PostToolUse, 2 failure, 8 Stop and 1 SessionEnd. Dispatchers expand these into additional logical subhooks; this count is not a measurement of processes per call. [Flags](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/hook-flags.js#L65-L139), [hook config](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/hooks/hooks.json).

The bootstrap resolves the plugin root, constrains script paths, reads bounded input and dispatches exported `run()` functions in-process when supported. It suppresses raw input echoed on stdout to avoid reinserting tool payloads into transcripts. Several resolution, spawn and top-level failures deliberately return exit 0: **successful hook exit often means “no opinion,” not “check passed.”** The PostToolUse dispatcher merges structured blocks/context, preserves a block despite sibling failures and otherwise logs exceptions and continues. [Bootstrap](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/plugin-hook-bootstrap.js#L193-L208), [failure paths](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/plugin-hook-bootstrap.js#L293-L354), [output merging](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/posttooluse-dispatcher.js#L202-L285).

Host parity cannot be assumed. The inspected Codex plugin references `hooks/codex-hooks.json`, which registers **SessionStart only**, whereas the Claude config has the full lifecycle. Its interface description also still says 281 skills despite 328 primary sources. Count actual files and supported event registrations, not marketing strings. [Codex manifest](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/.codex-plugin/plugin.json#L23-L29), [Codex hooks](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/hooks/codex-hooks.json).

## Memory and learning: three different stores

### Portable Memory Vault

`unified-memory` is guidance over a separate `ecc-universal` runtime. It stores `ecc.memory.v1` Markdown documents in project, team or user scopes. Writes are create-only and always `trust: unreviewed`; normal recall selects active records, while direct reads retain historical inspection. User scope requires explicit selection and an opt-in for the MCP surface. A harness label routes records; it does not authenticate a person. The optional MCP exposes save/search/read/doctor and no promotion, overwrite, import or shell tool. [Skill contract](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/unified-memory/SKILL.md#L14-L102), [MCP boundaries](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/unified-memory/SKILL.md#L173-L199).

The code uses trusted-root checks, non-symlink regular-file reads and create-only publication through a private temporary file, `fsync` and hard link. Known secret patterns reject a write. Search is deterministic lexical scoring: title phrase 20, body phrase 5; per token, title 8, tag 6, metadata 3 and bounded body occurrence score. The scan caps are **5,000 entries and 16 MiB**; document/body limits are 128/64 KiB. Search returns diagnostics and direct lookup fails incomplete scans instead of reporting a false absence. [Publication](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/memory-vault.js#L191-L241), [save](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/memory-vault.js#L296-L343), [scan constants](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/memory-vault.js#L30-L36), [ranking](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/memory-vault.js#L538-L577), [incomplete reads](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/memory-vault.js#L668-L688).

**DIRECTOR:** adapt the interchange schema, explicit scopes, create-only provenance and incomplete-result semantics. This implementation is not the requested massive external memory service: it has no semantic index, automatic contradiction resolution or scalable incremental query service. Put authoritative source/version, observation time, correction/supersession and access policy in the external memory contract; retain lexical lookup as a small local cache or fallback. Secret regexes remain a backstop, not permission to ingest private content indiscriminately.

### Continuous-learning instincts

Pre/post observation hooks extract tool name, session/project, cwd and up to 5,000 characters each of selected tool input/output, then scrub recognizable secret patterns into JSONL. Minimal, disabled, automated and selected path/agent sessions are deliberately skipped. The background observer is **disabled by the checked-in default config**; when enabled, it samples the latest 500 lines, asks a Claude CLI process to read/write instinct files and uses a configurable model defaulting to `haiku`. It requests `Read,Write` tools, which is not a filesystem scope boundary. It suppresses observation of its own subprocess. [Capture and scrub](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/hooks/observe.sh#L480-L591), [skip guards](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/hooks/observe.sh#L79-L116), [default config](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/config.json), [observer launch](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/agents/observer-loop.sh#L384-L401).

The observer converts repeated behavior into trigger/action/evidence records with heuristic confidence. SessionStart selects instincts at default confidence ≥0.7, ranks confidence plus stack relevance, favors project IDs and injects at most six. These are behavior-changing instructions, unlike the vault's unreviewed evidence records. [Observer prompt](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/agents/observer-loop.sh#L268-L315), [selection/injection](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/session-start.js#L492-L532).

The implementation contradicts an unconditional “100% reliable” interpretation. Native Windows analysis skips by default because of noninteractive hangs; other code explicitly diagnoses observers killed after startup and missing analyses. Archival requires both process success and one exact final completion record, which improves on exit-status-only checks but still trusts a model assertion rather than independently verifying every required instinct write. Sampling 500 lines and subsequently archiving the whole observation file also does not establish every observation was analyzed. [Windows/sample](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/agents/observer-loop.sh#L203-L247), [survival diagnostic](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/hooks/observe.sh#L714-L770), [completion/archive](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/agents/observer-loop.sh#L440-L469).

**DIRECTOR:** adapt only an explicit, budgeted observation-to-proposal path. Prefer metadata and user-approved lessons over raw I/O capture. Learned content must stay quarantined until evidence review; repeated observations or confidence are not authority to install rules, grant permissions or override a correction. Enabling a provider-backed observer sends selected observations to that provider through its CLI; “local files” is not an end-to-end no-egress guarantee.

### Session summaries

Session-end/PreCompact summaries are a third persistence path. The helper extracts recent user/assistant turns and invokes a model through `claude -p`; the call inherits the environment and uses recursion markers. SessionStart wraps old summaries in a historical-only notice and caps total injected context at 8,000 characters by default. The wrapper is useful, but still prompt guidance. [Summary call](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/llm-summary.js#L134-L215), [historical wrapper](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/session-start.js#L719-L745).

Concrete misleading-state example: PreCompact appends **“Context was summarized”** even when the transcript is absent or the LLM summary is unavailable; the accompanying log accurately says only an event was recorded. Do not turn that persisted sentence into a completion receipt. [Fallback paths](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/pre-compact.js#L148-L161).

## Context, routing and cost

`strategic-compact` combines latest transcript usage with a secondary tool-call counter and only suggests compaction. `context-gate` adds opt-in checkpoint guidance; its own contract says it does not block tools, reserve a path, write/verify the checkpoint or close the session. Summary subprocesses and repeated startup injection are additional costs. **Headroom should remain the single context-management owner in DIRECTOR; ECC should provide observations or transferable checkpoint fields, not a second compaction policy.** [Suggester](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/suggest-compact.js#L15-L43), [context-gate contract](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/context-gate.js#L3-L26), [checkpoint limitation](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/context-gate.js#L165-L170).

`cost-aware-llm-pipeline` is a cookbook, not a production model router. It chooses a stronger model from character/item thresholds, retries narrow transient exceptions and records cost after a call. Checking an existing `over_budget` property is not reserving the next call's maximum exposure or controlling parallel spend. Use eval-calibrated routing and an atomic budget reservation in the core. Do not adopt embedded prices or “cheaper” multipliers without verifying current provider contracts. [Routing](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/cost-aware-llm-pipeline/SKILL.md#L21-L78), [composition](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/cost-aware-llm-pipeline/SKILL.md#L129-L153).

The executable cost tracker reads transcript usage, deduplicates message IDs and records cumulative rows. It optionally prefers a fresh per-session harness-cost file over rate-table estimates. This is accounting, not spending authorization. A cumulative session row must not be summed once per Stop. `prompt-caching-strategy` supplies the sounder principle: stable authorized prefixes, tenant-aware keys and actual cache/cost counters; caching does not expand the context window. [Tracker](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/cost-tracker.js#L140-L207), [authority preference](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/cost-tracker.js#L256-L266), [cache contract](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/prompt-caching-strategy/SKILL.md#L20-L61).

## Verification and coordination semantics

`verification-loop` is an agent-run build/types/lint/tests/security/diff procedure, with a valuable explicit distinction between local checks and target acceptance. Its secret grep examples are narrow triage, not security certification. The normal executable quality hook runs selected formatter checks, logs failures only when its strict flag requests it, catches errors and returns the raw input. Even that “strict” mode does not produce a blocking result. Stop formatting/typecheck batches edited JS/TS files and catches exceptions; it can alter files and must not race another formatter. [Verification phases/acceptance](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/verification-loop/SKILL.md#L21-L105), [advisory quality hook](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/quality-gate.js#L88-L153), [Stop batch](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/stop-format-typecheck.js#L228-L251).

Do not confuse three similarly named gates:

| Mechanism | Actual result | DIRECTOR treatment |
|---|---|---|
| `quality-gate.js` | Formatter telemetry; logs/no-op paths | Advisory evidence only |
| `delivery-gate` | File-mtime/edit-count and disk checks, with one-block recursion escape | Adapt health signals; reject “touch a learning file” as completion proof |
| `verification-loop` | Model-followed validation procedure | Compile project-owned acceptance checks into independently recorded receipts |

`skill-comply` is a real evaluation runner: it creates fixtures and runs `claude -p` with Read/Write/Edit/Bash/Glob/Grep, parses traces and uses LLM classification followed by deterministic temporal checks. That is a useful offline experiment, but scenario setup containment is not proof that the model's allowed Bash has a complete host security boundary. Model grading and hook-promotion recommendations require independent review and spend limits. [Runner](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/skill-comply/scripts/runner.py#L81-L132), [grader](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/skill-comply/scripts/grader.py#L119-L192), [delivery limits](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/delivery-gate/SKILL.md#L19-L37).

The team/RFC/orch families mostly provide planning contracts: owners, scopes, dependencies, worktrees, handoffs and merge gates. They are useful concepts, but multiple orchestrators would compete with the core and Ponytail. The GitHub coordination implementation has a concrete race: `applyClaim` reads, checks and edits an issue without atomic ownership, explicitly documenting the double-claim risk. Its `applyValidate` establishes that dependency issues are closed; it does not execute the task's acceptance tests. “Validated” there must not mean DIRECTOR task completion. [Team contract](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/team-agent-orchestration/SKILL.md#L19-L84), [claim race](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/github-coordination/actions.js#L38-L80), [validation meaning](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/lib/github-coordination/actions.js#L147-L189).

By contrast, the operator-approval reference has a stronger narrow mechanism: trusted exact text/hash/epoch/destination snapshots, `BEGIN IMMEDIATE` claims, one committed begin-dispatch transition, and unknown outcomes held without automatic retry. It explicitly does not authenticate the operator, send transport or guarantee exactly-once delivery. Adapt these distinctions into the core effect gateway. [Approval contract](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/operator-approval-loop/SKILL.md#L83-L135), [reference code](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/operator-approval-loop/references/approval_claims.py#L31-L105).

## Security and composition conflicts

**GateGuard is fact-forcing friction, not action approval.** For a destructive command it hashes the command, permits an already-checked key, otherwise marks the key checked and denies the first attempt with a message. That retry path does not independently verify the requested facts or human consent. Parse errors allow; some state failures allow with warnings. Keep consequential actions behind the core policy/effect gate regardless of ECC output. [Destructive retry](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/gateguard-fact-force.js#L2795-L2806), [parse behavior](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/gateguard-fact-force.js#L2528-L2538).

Hookify implements bounded condition matching, restricted regex evaluation and structured warn/deny outputs. Tracked workspace rules are excluded by default unless the operator opts in, which is a useful supply-chain boundary. Invalid configuration is intentionally nonblocking. Config protection blocks many existing linter/formatter configs but intentionally excludes test/build configuration and allows first creation. Neither should be described as a complete anti-tamper policy. [Hookify trust selection](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/hookify-runtime.js#L363-L378), [outputs](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/hookify-runtime.js#L602-L640), [config scope](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/scripts/hooks/config-protection.js#L100-L124).

| Conflict/privilege | Source mechanism | DIRECTOR rule proposed |
|---|---|---|
| Duplicate observation or compact hooks | Plugin auto-registration plus manual snippets; both skills explicitly warn against copying twice | One registry entry per semantic event/handler/version; reject duplicate activation |
| Multiple context managers | ECC reminder, context gate, summary, startup injection and Headroom | One context controller; observers publish telemetry only |
| Multiple task/completion authorities | `.stories`, GitHub labels, RFC/orch agents and core/Ponytail | One task store, atomic leases/fencing and acceptance receipts |
| Competing engineering workflows | ECC orch/TDD/council/review and Superpowers | Select one active workflow; call narrow ECC capabilities as subordinate actions |
| Automatic learning authority | Confidence-tagged instincts injected as active behavior | Untrusted lessons cannot alter policy/skills without reviewed promotion |
| Provider/network side effects | Observer/summary/model graders; Exa/fal/VideoDB/social/payment/MCP integrations | Explicit egress scopes, credential handles, budgets and effect-bound approvals |
| Hidden formatter writes | Async edit checks and Stop batch formatting | One file owner/formatter stage; include formatter changes in reviewed diff |
| Secrets in capture/output | Partial tool I/O scrubbing and pattern-based memory rejection | Minimize capture, redact before persistence/egress, never echo detected values |
| Installation changes user configuration | Setup skills, package downloads, MCP/hook examples | Stage a reviewed adapter package; no blanket installer or inherited config permissions |

Duplicate-hook warnings are explicit in [learning setup](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/continuous-learning-v2/SKILL.md#L154-L180) and [compact setup](https://github.com/affaan-m/ECC/blob/4adeee6732a12d1540f49a4d50a38ce8c97f9a53/skills/strategic-compact/SKILL.md#L41-L59). No installed behavior, timing overhead or provider privacy guarantee was measured in this research.

## Complete disposition and rollout recommendation

Every one of the 331 directory identities has its own activation, mechanism, category, rationale and source paths in both inventories. **Adopt means adopt the principle, not install the upstream plugin.** Adapt means redesign against the core's contracts. Optional means lazy domain routing. Reject means exclude from DIRECTOR's default control stack, not that the upstream project has no legitimate standalone use.

| Decision | Count | Examples / reason |
|---|---:|---|
| Adopt principles | **18** | Harness/architecture audit, failure introspection, change-impact, contract-first, iterative retrieval, dependency lanes, test mapping, cache boundaries and production evidence |
| Adapt | **71** | Memory interchange, learning proposals, cost/verification evidence, config health, exact operator approvals, selected planning/UI feedback mechanisms |
| Optional on demand | **220** | Language/framework/testing cookbooks; research, content, media, network, business and scientific adapters. Their provider and domain privileges remain separate |
| Reject from default stack | **22** | Alternate kernels/orchestrators, host-specific installation guides, repository-local examples, archival learning v1 and heuristic token-depth controller |

The 18 adopted principles are: `agent-architecture-audit`, `agent-harness-construction`, `agent-introspection-debugging`, `change-impact`, `click-path-audit`, `context-and-decisions`, `contract-first`, `iterative-retrieval`, `latency-critical-systems`, `loop-design-check`, `mcp-dependency-review`, `module-regression`, `parallel-execution-optimizer`, `production-audit`, `prompt-caching-strategy`, `regex-vs-llm-structured-text`, `research-ops`, `test-collaboration`.

Stage ECC as immutable, pinned **data** behind a capability registry. Select a small skill packet from current intent/stack, validate its host/tool/egress requirements, and keep its text below higher-priority session policy. Record source commit/license and the reason it was selected. Loading a cookbook never grants its suggested shell, network, publish or spending privileges. Parent-stack recommendations about Headroom/Ponytail/Superpowers are composition proposals; their current implementations must be established by their own source analyses.

### Universal-domain capability selection

DIRECTOR's scope is broader than software delivery: websites, model training, research, documents/data and any other supported work. ECC has useful breadth here, but a broad library is not a universal verifier. The core should select both a **capability** and a **domain-specific acceptance contract** from the requested outcome and available tools; a successful agent response, file write or process exit cannot substitute for that contract.

| Domain | ECC mechanism examples | Acceptance evidence DIRECTOR still needs |
|---|---|---|
| Websites and applications | `frontend-design-direction`, `browser-qa`, `click-path-audit`, framework recipes | Rendered journeys, actual target behavior, accessibility and deployment checks where requested |

## Five largest design lessons

1. **A gate name is not a guarantee.** Distinguish advisory warning, deny-first retry friction, acceptance test and trusted approval in typed interfaces. Cheapest test: feed a failed formatter result, skipped hook and “dependency closed” status into a simulated completion transition; all must remain insufficient.
2. **Memory evidence and learned instructions require separate trust.** Reuse scoped immutable records and explicit supersession, but quarantine behavioral proposals. Cheapest test: save an old permission/false completion, then a correction; retrieval must preserve the correction and grant no effect authority.
3. **One controller should own each loop.** Multiple compaction hooks, summaries, task ledgers and review pipelines multiply work and contradictory transitions. Cheapest test: replay a recorded event stream through a dry-run registry and count context decisions, task mutations and external effects; each should have one accountable owner.
4. **Atomic ownership and unknown outcomes matter more than agent count.** GitHub read/check/write claiming is insufficient; approval claims show the stronger pattern. Cheapest test: race two claims and crash after begin-dispatch; expect one winner and an unresolved held effect, never an automatic duplicate send.
5. **Evaluate cost per verified outcome, including the harness.** Include observation, summary, review, grading, retries and idle/background failures. Cheapest test: compare a minimal packet against the same task with learning/reviews enabled on fixed fixtures, measuring accepted outcomes and all actual usage. No savings number is justified before that experiment.

## Remaining evidence limits

This report establishes the pinned file surface and selected mechanisms from source. It does not establish live provider support, current prices, functional success on Windows, security under hostile concurrent local writers, translation correctness, scale or performance. Tests present upstream were inspected where relevant but not executed. Complete machine reads of all skill bodies and supporting runtime files do not mean all code paths received an independent security audit. The inventory makes that distinction per skill so a later implementation can prioritize the exact adapters it will actually enable.
